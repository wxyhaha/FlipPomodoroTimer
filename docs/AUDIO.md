# 计时提示音

## 触发与声音

| 场景 | 声音 |
| --- | --- |
| 新计时开始、换面重新计时、暂停后恢复 | 柔和电钢琴 G4（392Hz）→ B4（493.88Hz），音符尾音重叠衰减，共 1.03 秒（含 150ms 静音尾部） |
| 倒计时首次进入完成状态 | 柔和电钢琴 G4 → B4 → D5（587.33Hz）→ G5（783.99Hz），共 2.10 秒（含 150ms 静音尾部）；不循环重复 |
| 普通按键/切页 | 原有 15ms 短按键音；不打断正在播放的计时提示 |

确认完成、重置或开始新计时会取消旧的完成提示。切到时钟页本身不会取消完成提醒。开始/完成事件在本轮全部状态变化处理后统一判断，避免一次动作多次排队。

## 实现与硬件

使用板上 ES8311、原有喇叭输出和功放使能接口。开始与完成音采用用户选定的柔和电钢琴合成音色：基音加少量二、三次谐波，指数衰减与短淡入淡出，多音符尾音重叠。基准振幅为满幅的 28%，比旧版持续高频双音更柔和；ES8311 驱动音量参数改为 75，对应 DAC 寄存器 `0x32=0xBF`（0dB）。普通 15ms 按键音保持原实现。使用 16kHz、16 位双声道 I2S，两个声道写入相同信号。

播放由独立 FreeRTOS 后台任务执行，主循环只投递请求；提示音不在界面线程中等待完成。请求队列只保留最新有效提示，开始新计时可替换旧提醒。通过短块检查取消，随后静音排空已排队的数据；不保证样本级瞬时取消。

每段连续播放期间保持功放开启。结尾额外写入 160ms 静音排空，再关闭功放，避免尾音仍在 DMA 队列时就关断。当前 Arduino 3.3.11 I2S 配置为 6×240 帧，16kHz 下约 90ms；升级驱动时需重新核对。取消时先静音，再排空旧数据，避免旧尾音混入新提示。

## 不必等待完整番茄周期的喇叭测试

设备完成启动后，在 USB UART（115200）发送 `AUDIO_TEST` 并换行，会依次播放短开始音、900ms 间隔和长完成音；不修改当前计时状态、剩余时间或预设时长。实际翻面开始新计时可能中断此测试，测试时保持设备不动。

可使用串口工具，也可在安装可选依赖 `pyserial` 后运行：

```powershell
python -m pip install pyserial
python tools/test_audio.py --port COM3
```

该工具检查 `[AUDIO] cue=speaker-test finished`，只能证明软件播放路径完成。是否接好喇叭、声音是否清楚以及音量是否合适，需要实听。脚本不重置设备，不应与其他串口监视器同时占用同一端口。

## 音色资源复现

`PianoAudio.h` 是原创合成 PCM，不使用外部音乐采样。运行 `python tools/generate_piano_audio.py`（Python 3.10+，仅标准库）重建头文件及 `build/audio-previews/piano-start.wav`、`piano-completion.wav`。正常编译使用已入库头文件，无需安装音频库或连接网络。

PCM 为 16kHz 单声道 16 位，开始 16,480 个采样、结束 33,600 个采样，共占 100,160 字节只读采样数据。后台任务每次取 128 帧复制为双声道送入 I2S，不将整段声音复制到 RAM。与电脑试听采用相同音符和合成公式，采样率从 24kHz 改为 16kHz；小喇叭的实际音色仍需实听。

## 柔和电钢琴验证

用户已选定电脑试听中的柔和电钢琴。已接入固件并编译通过：Flash 1,597,527 字节（50%），静态 RAM 49,020 字节（14%），与旧音色相比静态 RAM 不增加。生成器重复运行得到逐字节一致的头文件，本轮编译日志为本地 `build/compile-piano.log`。COM3 烧录及写入校验通过（`build/upload-piano.log`）。`AUDIO_TEST` 软件播放完成，播放期间收到 4 条主循环状态，显示同步 `timeouts=0 healthy=1`；用户随后反馈刺耳破音，且主观音高、速度明显不同，本轮新音色未通过实听验收。以下“画面、声音都正常”是旧音色与接口修复的历史验收，不代表新音色已获实听确认。

## 电钢琴失真排查

PCM 头文件与生成器逐采样核对一致，开始/完成片段峰值分别约为满幅的 0.407/0.389，源采样未削波。I2S 与 PCM 均配置为 16kHz、16 位，单声道源复制至左右声道；尚未通过外部仪器测量实际时钟。

发现旧调用 `es8311_voice_volume_set(..., 100, ...)` 经本地驱动映射为 `0x32=0xFF`，根据 [ES8311 数据手册](https://files.waveshare.com/wiki/common/ES8311.DS.pdf) 第 25 页，该值是 +32dB，而 `0xBF` 才是 0dB。+32dB 足以导致当前 PCM 削波，不能将它解释成仅提高模拟喇叭音量。现改为参数 75（映射为 0xBF），启动时读回确认，失败则不启用音频。播放日志增加含 DMA 排空的耗时，便于核对时长。增益修正版编译通过（Flash 1,597,843 字节，静态 RAM 49,020 字节），COM3 烧录校验通过。启动读回 DAC 音量 0xBF，并报告 I2S 配置 16000Hz/16 位。测试序列播放耗时 4123ms（含排空），后续开始音耗时 1121ms；均为软件调用耗时，并非外部时钟测量。日志为本地 `build/compile-piano-gain.log`、`build/upload-piano-gain.log`。用户随后明确确认“正常了，接近电脑试听”：本轮增益修正后的破音消失、音高和速度观感已通过实听。保留柔和电钢琴 PCM 与 0dB 设置；完整倒计时自然到期和快速换面抢占仍待独立覆盖。

## 历史验证记录

首次音频版已编译、烧录；测试命令的软件播放完成，期间主循环继续运行，但用户未听到声音，不能视为声音验收通过。用户已确认 AUDIO 接口连接喇叭，且开发前曾正常发声。

后续排查黑屏时发现共享 TCA9554 总线构造参数错误：实际库参数顺序为 `rst, cs, sck, mosi, wire, address`，旧代码误用默认地址 `0x38`。这既影响 LCD 初始化，也使 EXIO3 功放控制未发送到板上 `0x20` 芯片。已修正为 `7, 0, 2, 1, &Wire, 0x20`。修正版编译通过（Flash 1,497,275 字节，静态 RAM 49,020 字节），COM3 烧录写入校验通过。

修正版测试命令播放完成，播放期间记录到 4 条主循环状态输出；用户明确确认“画面、声音都正常”。短开始音、长完成音片段已获实听确认，完整倒计时自然到期、连续快速切换时的抢占行为仍待覆盖。编译与烧录日志分别为本地忽略目录内的 `build/compile-display-fix.log`、`build/upload-display-fix.log`。

用户随后拔掉 USB 再重新插电，确认屏幕正常显示；这补充了软件复位之外的冷启动验收，详见 [硬件记录](HARDWARE.md)。

完整倒计时到期的状态触发与测试命令播放的音频片段分别记录，不能将片段测试当作完整周期验收。
